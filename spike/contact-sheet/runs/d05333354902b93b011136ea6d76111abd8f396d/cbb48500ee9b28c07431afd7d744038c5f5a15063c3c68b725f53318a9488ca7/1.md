**First read.** Your eye lands on the page title at top left, moves to the blue button at top right, then drops into the white cards. It reads as a calm, tidy invoicing app with a dark sidebar and gray canvas, built to one shell. Across the sheet, one tile catches your eye for the wrong reason: the green outlined pill "Export CSV" on tile 4 is the only control of its kind in the set.

**What it's for.** As you told me: six screens of one invoicing web app for small businesses, judged as a set for whether elements and alignment stay consistent.

**Verdict.** The set holds together very well. The layout is the same on every screen, and five of the six screens use the same header button. Tile 4 breaks the pattern: its top-right action is a green outlined pill instead of the solid blue rounded rectangle, so the one action on the Reports page looks like it belongs to another product.

**What would move it most**
1. **The Tile 4 header button breaks the button pattern (defect).** Tiles 1, 2, 3, 5 and 6 each put one solid blue button with a small corner radius at the same top-right spot ("New invoice", "Add client", "Request payout", "Save changes"). Tile 4's "Export CSV" sits in the same spot but is drawn as a fully rounded pill with a green outline, green text and no fill. That costs the user three things:
   - They have learned that the top-right blue button is "the thing to do on this page". On Reports the main action no longer looks like one. It looks secondary, or like a status tag.
   - Green already means "Paid" in the status pills on tiles 1 and 2, so a green pill-shaped control blurs a meaning the app has trained the user to read.
   - It's the one element in the set that looks like it came from a different design.

   Sources: Gerstner, *Designing Programmes* (elements of one kind share one style; a variant appears only where the rules call for it); WCAG 3.2.4 Consistent Identification (same function, same look across pages); Apple HIG on color for status and the semantic color convention (green means success). **Fix:** draw "Export CSV" with the same solid blue button component, same radius, used on the other five screens. If export really is a lower-rank action, use the system's own secondary style in the app's blue or neutral, not a new color and shape.

**Smaller things.**
- **Tile 2, sample data:** rows INV-0942 to INV-0937 repeat the clients, amounts and dates of INV-1042 to INV-1036 exactly. That reads as copy-pasted filler, and the dates run out of order with the invoice numbers. Use distinct data before showing this anywhere.
- **Tile 3, card heading:** the heading "Clients" repeats the page title right above it. Name what the card holds, or drop it. Tile 2 has the same issue more mildly ("All invoices" under "Invoices").
- **Amount columns on tiles 1, 2, 4 and 5 are left-aligned,** so the decimal points don't line up. Set them flush right with tabular figures (Bringhurst 4.4.3).
- **Tile 4, revenue bars:** the bars show no amounts and no scale, so "Revenue by month" can only be compared by length, never read. Label each bar with its value (Tufte, ch. 2).
- **Headline figures without a comparison:** the stat cards on tile 1 (Outstanding, Paid this month, Overdue) and the revenue bars on tile 4 have no prior period or target. "Average days to pay" on tile 4 shows how to do it ("Down from 23 days last quarter"). Give the others the same (Few).
- **Tile 2, no search or filter:** a list that will grow past 21 invoices needs a way to find one by client or status (Nielsen 7).
- **Tile 6, input borders:** the borders look pale against white. Check that they reach 3:1 (WCAG 1.4.11).
- **Tile 6, "Default payment terms":** it looks like a free-text field. A picker of fixed terms would stop typos (Nielsen 5).

**What's working.**
- **One grid on every screen.** Content starts at the same left edge beside the sidebar and ends at the same right edge. The title and subtitle sit at the same height, and the first card starts at the same y on all six tiles. Keep this. It's why the set feels like one product.
- **The table component is identical across tiles 1, 2, 3 and 5:** same small-caps header row, row height, hairline dividers and card padding. Tile 4's "Top clients" list reuses it too.
- **Status pills pair color with a word** ("Paid", "Due", "Overdue"), so status never relies on color alone.

**Where it could go further.**
1. Builds on finding 1: make the solid blue header button a rule of the whole system, one per screen and always top right, and write down the one secondary style, so the next screen added can't invent a third button (taste; Gerstner, *Designing Programmes*).
2. The Overview's stat cards (tile 1) and the Payments cards (tile 5) are the same component with different contents. Tile 5's cards carry a third line ("Arrives Nov 26", "Checking, First Harbor Bank") that tile 1's lack. Giving every stat card that context line would make the cards fully one pattern and give the bare numbers on tile 1 a point of reference (taste).

**Couldn't judge from a still.** Focus states on the nav and buttons. Whether the Invoices table (tile 2) scrolls inside its card or with the page.
