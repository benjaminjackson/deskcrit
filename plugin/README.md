# deskcrit plugin for Claude Code

This plugin gives Claude Code two skills. The `crit-loop` skill tells a coding agent how to check its UI work: capture the page, run the design-critic skill, fix the top findings from its work order, capture again, have a fresh critic recheck each finding, and stop when no ranked finding is left or two rounds in a row close nothing. The rules are in [docs/PRD.md](../docs/PRD.md).

The `design-critic` skill critiques a still image of a design the way a senior design director would. It starts a Claude agent that walks a checklist of guidelines. It needs no API key.

To look at a large image closely, the critic runs `scripts/crop.mjs`, which cuts a PNG into full-resolution crops about one screen tall, or crops one box, into a new temporary folder. The script uses only Node's own modules (it reads the PNG with `node:zlib`), so the installed plugin needs no install step and no image library. For a file other than a PNG of 8 or 16 bits per sample, an interlaced PNG, or a broken file, it prints one line that says why, and the critic looks at the whole image.

When the page's code or URL is available, the critic can run `scripts/measure.mjs PAGE --out FOLDER`. By default it renders the page in light mode at four viewports (desktop 1280 x 800 px, phone 390 x 844 px, tablet 768 x 1024 px, widescreen 1920 x 1080 px), and writes a full-page screenshot of each, one-screen crops of each, and `facts.json`, which `schemas/facts.schema.json` describes: per text block the font, size, line height, characters per line, and contrast, with a CSS selector and a pixel box, and per page the type sizes, text colors, spacing, left edges, and target sizes. The skills pass no viewport flag by default, and the critic gets every screenshot of the facts file in one crit. PAGE may be a local file with a hash anchor, such as `deck.html#3`: the script keeps the hash, so the page opens at that anchor, and `facts.json` records PAGE with its hash. The crit-loop skill picks each slide of a deck this way.

The script needs the `playwright` package and its Chromium, and it never installs them. An installed plugin has no `node_modules` of its own, so the script finds Playwright only in the project it runs from: it looks for `playwright` from the working directory. Node does that search in the usual way: in `node_modules` of the working directory, then in `node_modules` of each folder above it. Only when the script runs from a deskcrit checkout, with `GUIDELINES.md` and `packs/package.json` at the root of the repository, does it also find the copy in `packs/`. An installed copy of the plugin does not look in the folders above its own folder. A project that has only `@playwright/test` does not count, because the script loads the `playwright` package itself. If the script does not find it, run `npm install playwright` and `npx playwright install chromium` in the project. Without Playwright, the script prints one line that names the install commands and exits with code 4. The skill then shows you the commands and asks before it installs anything. If you say no, the critic works from the image alone and says so. Exit code 3 means the page cannot be opened.
