**First read.** The eye lands on the serif headline at top left, "Hire a narrowboat direct from the boatyard that keeps it". It moves down to the intro, then across to the white "Find a boat" card and its dark green Search button. The page reads as a calm, plain booking page for a boatyard. It is tidy and quiet, but it is all text and form fields, so it feels like a booking tool more than a holiday. The phone and widescreen views look the same as before: the phone stacks the headline, intro, form and routes in one column, and the widescreen centres the desktop layout with a lot of empty space. On the tablet, the form now has two columns, with Base beside Start date and Nights beside Berths, and the routes list moves up into the first screen.

**What it's for.** This page gets a visitor to search for a narrowboat to hire direct from the boatyard, and the reason it gives is that there is no agency fee (from the work order's crit).

**Verdict.** The tablet fix made the form shorter and easier to scan, and it brought the routes into view. It changed nothing else. The two things that most hold the page back are still there, and both need content that only the boatyard can supply: a price or other fact that backs the no-fee claim, and a real photo of a boat or a route.

**Finding status**
- no-fee-claim-without-number: open. The intro still says "no fee on top of the hire", and there is no price or other boatyard fact near the intro or the form at any viewport.
- no-picture-of-the-holiday: open. The hero is still only the headline and the intro at all four viewports, with no photo of a boat or a route.
- start-date-looks-like-free-text: open. The Start date field is still a plain box that holds "Sat 14 June", with no calendar icon or other date-picker cue at any viewport.
- tablet-form-fields-too-wide: closed. On the tablet, Nights and Berths now share one row, and the measured width of the Nights select is 289 px (it was 594 px).

**New problems.** On the tablet, the Start date input (43 px tall) now sits beside the Base select (40 px tall), so their bottom edges are 3 px apart in the same row. The difference is small, but you can see it now that the two fields are side by side. This is not a template tell.

**What would move it most**
1. The no-fee claim has no number behind it (open). It sits in the intro under the headline, at every viewport. The visitor reads "no fee on top of the hire" but has no price to judge it against, so the page's main selling point is still unproven. Put a fact that proves the claim near the intro or the form, such as a from-price per week for a boat at this base. Only the boatyard can supply that figure. Defect. Viewports: desktop, phone, tablet, widescreen.
2. The holiday page has no picture of the holiday (open). The hero is only text, at every viewport. People hire a narrowboat for the boat and the water, and the page shows neither, so it sells a form instead of a trip. Add a real photo of the boatyard's own boats or of a listed route, not a stock picture. The boatyard must supply it. Taste. Viewports: desktop, phone, tablet, widescreen.

**Smaller things.**
- The Start date field has no date-picker cue. Use a date input or add a calendar icon to the field (Nielsen heuristic 5). Viewports: desktop, phone, tablet, widescreen.
- On the tablet, the Start date input is 3 px taller than the Base select next to it. Give the input and the selects the same height so that the fields in each row line up. Viewports: tablet.

**What's working.**
- The new two-column form on the tablet pairs short values side by side. The whole card fits with room to spare, and the routes list is now in the first screen.
- The routes list puts the name on the left and "nights, locks" on the right in a muted grey. This makes the three trips easy to compare at a glance.
- There is one strong action. The dark green Search button is the only filled element on the page, so nothing competes with it.
