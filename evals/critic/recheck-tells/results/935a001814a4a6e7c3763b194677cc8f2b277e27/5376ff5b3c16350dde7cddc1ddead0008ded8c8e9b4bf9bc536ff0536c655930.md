# Recheck: Fernbrook Output dashboard

**First read.** The eye still goes first to the dark blue bar for array F. It then moves straight to the bright cyan outlines that now go around all five cards, which are the loudest lines on the page. The page still reads as a calm monthly output overview for a small solar co-op. The cyan outlines make it look like a stock template and give it a buzzing edge it did not have before.

**What it's for.** A co-op manager uses it to see how November's output compares with October and which arrays need a site visit. That is taken from the work order's findings.

**Verdict.** The fixes did not help the piece do its job, and they made it worse. Neither finding was touched. The only change is the card borders, which went from grey hairlines to bright cyan, and that is a template tell. The biggest problems now are the unexplained highlighted bar and the neon card outlines.

**Finding status**
- unexplained-highlighted-bar: **open.** The "Output by array" chart is pixel for pixel the same as before. Array F is still blue with only "2.3 MWh" above it, and no title or note says why it is picked out.
- fault-column-spacing: **open.** The "Arrays needing a visit" table is unchanged. "Array D, north roof" still ends near x≈410 and "Inverter offline 2 days" starts at x≈584, leaving a gap of about 170 px.

**New problems.**
- All five cards (the KPI row, "Daily output", "Output by array" and "Arrays needing a visit") now have a bright cyan 1 px border instead of a grey hairline. The viewer meets a neon edge around every surface. Cyan is a third hue that matches neither the chart blue nor the greys, and because every card is outlined, nothing stands out. This hits the template tells "Neon or bright colored borders" and "Every element highlighted".

**What would move it most**
1. **The highlighted bar has no stated reason.** This is in the "Output by array" chart. A viewer sees array F picked out but cannot tell if it is the best array, the worst one, or the one selected. A highlight needs to be explained in the chart itself (Tufte, *The Visual Display of Quantitative Information*). Fix: say in the title or a short note what the highlight means, for example that it marks the top array this month, if that is the reason. Only the maker knows the reason. **Convention.**
2. **Neon cyan card borders.** These are on all five cards. The outlines pull the eye away from the data, compete with the blue that should be the one accent, and make the page look like a generic template. The rule is that borders between surfaces should be hairlines at 6 to 10% opacity, and the accent should appear once or twice per screen (unslop, `references/tells.md` "Neon or bright colored borders" and "Every element highlighted"). Fix: go back to the light grey hairline from the before image. **Defect.**

**Smaller things.**
- In the "Arrays needing a visit" table, the Array and Fault columns are still about 170 px apart. Narrow the Fault column's start, or widen the Array column's share less, so each name and fault read as one line.

**What's working.**
- The KPI row pairs each November figure with its October value in small text underneath. That gives each number its comparison without adding any charts.
- The daily output chart sets November in blue and October in grey. The current month leads and last month sits back as context.
- The table right-aligns the Panels and Lost output numbers. They line up, so the rows are easy to compare.
