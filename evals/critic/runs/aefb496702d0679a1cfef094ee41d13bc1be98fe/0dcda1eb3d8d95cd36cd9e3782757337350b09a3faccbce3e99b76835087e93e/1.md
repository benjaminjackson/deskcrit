**First read.** The eye lands on "River ferry timetable," drops to the gray subtitle, and then goes to the left column. That column is "Period: Morning, Morning, Midday…", which is the one column a rider doesn't need. It reads as a calm, tidy web page for a small local service. It feels trustworthy but plain, closer to a default styled table than a designed timetable.

**What it's for.** I'm assuming this is a public page where a rider checks when the next ferry leaves north landing, whether it runs on their day, and when it reaches the quay. They glance at it, often on the move.

**Verdict.** The table is clean and readable, and a rider will get the right answer. But it's built like a data table rather than a timetable. The departure time doesn't lead, the times don't line up, and two facts a rider acts on are missing or hidden: when "spring season" starts and ends, and which sailings don't run every day.

**What would move it most**
1. **The first column holds the least useful data, so the eye starts in the wrong place.** "Period" sits in the leading column (x ≈ 120), but every time already tells you whether it's morning or evening. "Morning, Morning, Midday, Midday…" adds nothing a rider would miss. Because it comes first, a rider reads a label, then jumps about 240 px right to find the time they came for. Over 7 rows that's 7 wasted jumps, and the useful content gets pushed across a 1080 px wide table. *Defect / common sense*: no source on the list rules on this, but it's the first thing a rider meets. The fix is to make "Leaves north" the first column. Then either drop Period or turn it into quiet group dividers between rows. Once the column is gone, the table can also get narrower, so the leave time, arrive time, and days sit close together.
2. **The exceptions look exactly like the rule.** In the "Runs" column, "Weekdays" (12:40, 17:10) and "Weekends" (19:30) are set the same as "Daily". These are the rows that catch a rider out: someone planning a Saturday 12:40 crossing has to read every cell to find out it doesn't run. *Defect*, because it misleads by omission on what the rider acts on. The fix is to make the exceptions stand out and let "Daily" go quiet. For example, set Daily in the muted gray already used in the subtitle, or leave it implied and mark only the exceptions in weight. Keep it in words, not color alone.
3. **"Spring season" has no dates.** The subtitle "North landing to market quay, spring season" doesn't say when spring starts or ends, so a rider in late May or early March can't tell whether these times apply to them. This is a date the viewer acts on, so it's a *defect*, not style. The fix is to add the season's start and end dates (only the operator knows them) and, if it applies, the year.
4. **Times are set in proportional figures, so the columns don't align.** In both time columns, "11:00", "11:12" and "17:10" are visibly narrower than "06:40" or "12:52", so the colons drift left and right down the column (crop of x 340–760). In a timetable the eye compares times vertically, and a ragged column makes that slower. This is a *convention* (Bringhurst, *Elements of Typographic Style* §4.4.3: columns of figures are tabular and aligned). The fix is to turn on tabular figures; the face shown appears to support them.

**Smaller things.**
- Column headers "Leaves north" / "Arrives quay" are clipped versions of "north landing" and "market quay". They're readable in context, but "Leaves North landing" / "Arrives Market quay" (or just "Departs" / "Arrives", since the subtitle names the route) reads less like shorthand.
- There's no return sailing or link to it. If quay → north exists, a rider will look for it on this page. That's the maker's content to supply.

**What's working.**
- The restraint in the rules: light hairlines between rows and a slightly stronger rule under the header. They separate the rows without boxing them in. Keep this when revising.
- A clear three-level scale: a bold title, body-size cells with the header row set apart by weight rather than size, and a smaller gray subtitle. No sizes compete.
- Generous row height (~57 px). Each row is easy to track across even at this width.

**Where it could go further.**
1. Builds on finding 1. Let the departure time own the page: set the "Leaves north" times noticeably heavier or larger than everything else in the table, so the column reads like a clock face down the page. A rider's question is "when's the next one?", and the answer should be the loudest thing after the title. *Taste.*
2. Commit to the 12-minute crossing. Every arrival is exactly 12 minutes after departure. Saying that once near the subtitle could replace the whole "Arrives quay" column, halve the table's width, and leave room for the departures and days to breathe. *Taste*; only do it if the crossing time really is fixed.
