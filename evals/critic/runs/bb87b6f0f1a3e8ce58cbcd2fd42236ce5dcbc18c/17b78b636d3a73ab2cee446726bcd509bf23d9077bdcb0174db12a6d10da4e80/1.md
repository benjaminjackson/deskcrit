**First read.** The eye lands on "Book a workshop seat" and then has nowhere to go. The rest is a stack of four identical empty boxes with bold labels between them. Each label sits right under a box, so at a glance "Preferred date" looks like the caption of the box above it. The eye keeps going down and finds no button, only blank space. It reads as an unfinished internal booking form. It feels sparse and orderly, but it doesn't help you.

**What it's for.** My assumption: a public web form where someone reserves one or more seats at a workshop the organizer runs.

**Verdict.** It doesn't work yet. There is no way to submit the booking, and every label is spaced so it seems to belong to the wrong field. On top of that, the fields leave the user to type in everything the form should be offering them: which workshop, which dates, how many seats.

**What would move it most**
1. **There is no submit button.** After the "Notes for the host" box the form just stops, with about 250 px of empty white below it. Someone who fills in all four fields has no way to book. Nothing even tells them the page is a dead end, and nothing confirms they're in the right place to finish. *Defect.* The form needs exactly one primary button, filled and high-contrast, set right under the last field on the same left edge as the fields. Material Design and Apple HIG both say one primary action per view should dominate. Its label should name the result, as a verb plus what it books (for example "Book seats"), not "Submit". If a price or a confirmation step comes before the commitment, say so next to the button.

2. **Each label sits closer to the wrong field.** Each label sits about 15 px below the box above it and about 40 px above its own box. By proximity, the eye pairs "Preferred date" with the Workshop name box, "Number of seats" with the date box, and so on. "Workshop name" looks like it has no box, and the last box looks like it has no label. People will hesitate, and some will type the date into the name box. *Defect* (Arnheim and Wertheimer on proximity; Wroblewski on label placement). Reverse the spacing: put each label close above its own field, about 6 to 8 px, and leave a clearly bigger gap, about 24 to 32 px, between one field group and the next.

3. **Every field is a blank text box, so the user has to remember and type what the form should offer.** "Workshop name" asks the user to recall and spell a title, when the form should list what can be booked. "Preferred date" is a free-text box with no format shown and no picker. That invites "next Tues", "3/4" and other values that can be read two ways, and on a booking a wrong date is the error that costs the most. "Number of seats" doesn't look like a number input, has no default and shows no limit. "Notes for the host" is a single line, so it suggests a word or two when it wants sentences. *Defect* (Nielsen 5, error prevention; Nielsen 6, recognition rather than recall). Give each field the control that fits its data:
   - **Workshop:** a list of the workshops on offer.
   - **Date:** a picker limited to the dates actually available. If any date works, a date input that shows its format.
   - **Seats:** a number stepper with a sensible default.
   - **Notes:** a multi-line text area.

   It's common sense, and my own view, that defaulting to the seats people most often book saves a step. If the workshop is already known when someone reaches this page, it should arrive prefilled.

**Smaller things.**
- No field is marked as required or optional. "Notes for the host" is almost certainly optional, so put "(optional)" after its label, or mark the required fields with an asterisk and explain it once (Budiu, NN/g).
- The form doesn't collect a name or email. A booking normally needs a way to confirm with the person. If the page already knows who the user is, ignore this; if not, the maker needs to decide what's required.

**What's working.**
- The type scale is clean. There are two levels, a large bold heading and smaller bold labels, in one face and one dark color, and the heading is obviously in charge. Keep it this restrained.
- The heading says what the page does as a plain verb phrase ("Book a workshop seat") instead of a category name like "Registration". Keep that voice for the button.
- There is one left-aligned column with a consistent left edge and field width, which is the right shape for a short form.

**Couldn't judge from a still.**
- Focus indicators on the fields, and whether they're at least 2 px and 3:1.
- Validation timing and error messages, especially for the date.
