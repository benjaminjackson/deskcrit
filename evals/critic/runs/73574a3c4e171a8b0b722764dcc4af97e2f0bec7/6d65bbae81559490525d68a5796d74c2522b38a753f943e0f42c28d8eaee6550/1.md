**First read.** At thumbnail size this reads as one product. The sidebar, page title and subtitle, white cards on a pale gray background, and the single green accent repeat on every screen. It stops feeling like one product in three places: the Clients screen sits slightly off the shared content edges, the New invoice screen highlights the wrong nav item, and the Invoices list uses a button label that belongs to the form.

**Verdict.** The set mostly holds together. The biggest break is on tile 4: the sidebar says you are in Reports while the page is New invoice, so the one element that tells you where you are gives the wrong answer.

**Breaks**
1. **The active nav item matches the current page.** Tiles 1, 2, 3 and 5 keep this; tile 4 breaks it. On the New invoice screen the green pill is on **Reports** (y ≈ 203–243), not on Invoices. Someone who came from Invoices to make a new one sees the sidebar say they have left Invoices for a different section. Anyone who checks the sidebar to get their bearings, or to find their way back, gets the wrong answer. This is a **defect** (Nielsen 4, *Consistency and standards*: the same component has to mean the same thing everywhere in the set). Fix: highlight Invoices on this screen, since New invoice sits under that section.

2. **Content keeps one left and right edge.** Tiles 1, 2, 4 and 5 keep this; tile 3 breaks it. On every other screen the title, cards, table and form start at x = 264, and the cards and table end at x = 1240. On Clients the title and both card rows start at x = 272 and end at x = 1232, so they're inset 8 px on each side. When you click from Overview to Clients, the three stat cards are identical but shift 8 px inward and narrow. That reads as a jump and as a second, unrelated layout, not as a deliberate choice. This is a **defect** in craft (Gerstner, *Designing Programmes*; Müller-Brockmann, *Grid Systems*: repeated elements follow one program). Fix: put Clients on the same 264–1240 content column as the other screens.

3. **One button label means one action.** Tile 4 uses **Save invoice** for its real job, submitting the form. Tile 2 breaks this. On the Invoices list the same filled green **Save invoice** button sits above a table, where there's nothing to save, next to a **Preview** with nothing selected to preview. The user sees the label they'll later meet on the form and can't tell whether it creates an invoice, saves something on this page, or does nothing. This is a **defect** (Nielsen 4: the same term means the same action everywhere). Fix: name the list-page button for what it does there. If it opens the form, it's the entry to New invoice. Keep **Save invoice** only for the form's submit. Drop Preview from the list, or tie it to a selected row.

**Smaller things.**
- Tile 3: the client cards reuse the nav icons (house, list lines, bar chart) as decoration, in green. On every other screen those icons mean Overview, Invoices and Clients, so here they seem to say something about each client that they don't. Use one neutral client mark, or none.

**What's working.**
- The page header is identical on all five screens: same size of title, same gray subtitle, and the same 264 px start except on tile 3. It anchors each screen in the same place.
- The stat cards and the invoice table appear on two screens each with the same borders, radius, padding and status pills, so they look like the same component wherever they appear.
- There's one green, used for primary buttons, the active nav item, pills and toggles, so green always means "active or primary" across the set.
