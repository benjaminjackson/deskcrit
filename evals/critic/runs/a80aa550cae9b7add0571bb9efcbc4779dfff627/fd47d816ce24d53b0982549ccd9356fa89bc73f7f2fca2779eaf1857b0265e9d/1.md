**First read.** The two versions are identical except for the borders. In version 1 the eye goes to the five heavy black outlines before it reads any words, so the page looks like a wireframe of boxes. In version 2 the outlines drop back to pale hairlines, and the eye goes from "Your account" to the four bold card headings and then into the content. Version 2 feels calm and finished, and version 1 feels heavy and boxed in.

**What it's for.** I'm assuming this is the account overview page of a small online shop, where a returning customer checks their details or their latest order and jumps to the thing they want to change.

**Verdict.** Version 2 does the job better. The only change is the border weight, and it decides which version reads first as content and which reads first as containers. Version 2 still has a lot of empty space at the bottom of every card, which makes the page look unfinished.

**What would move it most**
1. **Border weight (the change between versions).** In version 1, each card and the sidebar has a dark outline about 2 px thick. It is the strongest contrast on the page, stronger than the headings. A viewer scanning for "where's my order" sees a grid of boxes first and has to look past the frames to read the labels. The outlines are doing work the background already does, because the white cards on the off-white page already separate the groups. Version 2 makes the borders light enough that they only hold the edge, which lets the headings lead. This follows Refactoring UI (Wathan and Schoger): use fewer borders, and when you need one, make it quiet so it doesn't compete with content. This is a defect in version 1, because the hierarchy is inverted and the content comes second. Version 2 fixes it.
2. **Empty card bottoms (version 2, remaining).** All four cards are the same fixed height, and the content stops about halfway down. Under "Edit details", "View all orders", "Manage addresses" and "Change card" there are roughly 100 to 140 px of nothing. The sidebar has the same gap below "Sign out". The page looks like it is waiting for content that never loaded, and it pushes the bottom row further down than it needs to be. Let the cards size to their content, keeping the two cards in each row the same height. Or use the space for something the customer would want, such as a link straight to order 48213. This is taste, but it's a strong opinion: the empty space is the most visible flaw left.

**Smaller things.**
- Sidebar: the current page is marked only by bold on "Account". A background tint or a side bar on the active item would show more clearly where you are.
- Sidebar: "Sign out" uses the same style and spacing as the menu items. Set it apart with a divider or extra space, because it does something different from the other items.
- Recent order card: "View all orders" is the only link, so there's no way to open this specific order. Make "Order 48213" itself a link.

**What's working.**
- There's a clear type scale: the page title, the card headings, body text and blue links. These are four distinct levels, and each one has an obvious job.
- The copy is concrete and needs no decoding, for example "Card ending 4417, Expires 09/28" and "Two linen pillow cases, Delivered 15 October". Each card's link names the exact action, such as "Change card" or "Manage addresses".
- The 2×2 grid lines up neatly with the menu order (Orders, Addresses, Payment), so it's easy to predict where things are.

**Couldn't judge from a still.** Hover and focus states on the links and the menu, and how the 2×2 grid reflows on a narrow screen.

Better: version 2
