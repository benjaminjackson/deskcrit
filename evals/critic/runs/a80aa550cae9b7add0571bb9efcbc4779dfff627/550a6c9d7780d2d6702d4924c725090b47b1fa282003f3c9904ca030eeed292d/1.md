**First read.** In both versions the eye lands on the "Release notes" title first, then moves down the left column. In version 1 it then steps through three bold version headings: 4.2, 4.1, 4.0. In version 2 those headings are regular weight and only slightly larger than the body text, so the eye slides past them into one grey block of prose. Both read as a quiet, carefully made changelog for a small photo-editing app.

**What it's for.** I'm assuming this is a release-notes page for existing users. They scan for a version number or date, then read what changed in it.

**Verdict.** Version 1 does the job better. Its bold version headings give the page the entry points that scanning needs. Version 2 removes the weight and keeps almost no size difference, so the headings stop working as headings.

**What changed, and why it matters**
1. **Version headings lost their weight (defect, in version 2).** Version 2's lines such as "Version 4.1, 2 September" are regular-weight serif, only a couple of points larger than the body and nearly the same colour. A reader looking for "the September update" can't pick out entries at a glance and has to read the start of each paragraph to find the boundaries. Version 1 makes the headings bold and darker. That is the right tool: separate levels by weight, not by another nearly-equal size (Wathan and Schoger, *Refactoring UI*: "bolder, not bigger"). Version 2 breaks this and ends up with two sizes that look like a mistake (Bringhurst). Keep version 1's treatment.
2. **Grouping is weaker in version 2.** In version 1 the bold heading anchors each entry, so the space between entries clearly separates three units. In version 2 the headings and body look almost the same, so the page reads as six similar lines-and-paragraphs rather than three entries.

**Smaller things (version 1).**
- The heading sits very tight to its paragraph, about the same gap as between body lines. Add a few pixels below each heading so it reads as a label rather than the paragraph's first line.
- The page uses four text sizes (page title, version heading, body, nav), which is a clean scale. Keep it.
- The right third of the page is empty. That's fine for three entries. Once the list grows, a sticky version index there would help readers jump to a release.

**What's working.**
- The copy is very good. Each line says who does what and what it means for you: "you can still drag the line by hand", "Presets from version 3 are converted the first time you open them". Keep this voice.
- The body measure is about 75–80 characters, a little over Bringhurst's 45–75 but comfortable here, and the line spacing is generous.
- The order is newest first, and every version has a full date.

Better: version 1
