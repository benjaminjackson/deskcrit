**First read.** My eye goes first to the three blue bars, then up to the row of four big numbers, then to "Overview." Within a second it reads as a monthly activity report for a small public library ("Marlowgate," for Ashcombe Public Library), for staff. It feels calm, tidy and trustworthy. After that first second it gets harder: the three blue bars sit at about the same height, so the charts look like they tell one story. On a closer look they turn out to be three unrelated numbers on three different scales.

**What it's for.** My assumption: library staff or a branch manager use it to check the month's activity, see how it compares with last month, and plan staffing around busy days.

**Verdict.** It's clean and mostly well made, but the charts look more informative than they are. Each one is on its own scale, has no axis, and labels only its peak, so the comparison the layout invites is false and most of the values can't be read. Nothing on the page tells you what to take away from it.

**What would move it most**

1. **The three weekday charts look comparable, but they aren't** (defect). The cards are the same size, the gray and blue bars are styled the same, and the peaks are about the same height: Loans 2,480, Returns 2,040, Holds 412. Holds placed looks about as busy as Loans when it's roughly a sixth of the volume. With no y-axis and no gridlines, a viewer can't spot this without reading the one small number over each peak. Charts set side by side for comparison should share a scale, or clearly show that they don't (Tufte, *The Visual Display of Quantitative Information*). Two ways to fix it: put Loans and Returns on one shared scale, since they're the same kind of count and staff will want to compare them, and set Holds visibly apart. Or keep the separate scales and put a light axis or a value on every bar so nobody has to guess.

2. **You can read only one value per chart** (defect). Six of the seven bars in each chart have no value, so the question this chart answers for a staffing decision ("how much quieter is Sunday than Saturday?") can only be estimated by eye. A dashboard chart should let you read what each mark measures (Tufte; Few). Fix: add a small value to each bar, or a light axis with two or three ticks. There's room in all three cards.

3. **The blue bar doesn't say what it means, and the titles don't say what was found** (defect, plus a taste point on the titles). Blue marks the busiest day, but nothing on the page says so. Without the number you'd have to work out that it's the maximum, and other dashboards use a highlighted bar for "today" or "selected." Meaning shown by color needs a second cue (WCAG 1.4.1). The titles also only name the topic ("Loans by weekday"), so each viewer has to find the point alone. My view as a designer: let each title or caption state the finding in words, using only what the data shows. For example, say which day is the peak, so the blue bar and the words make the same point.

4. **Nothing leads the page** (convention). The "Overview" title, the four KPI numbers and the three blue peaks all carry about the same weight, so the eye moves between the top row and the charts with no clear starting point. Tschichold and Hofmann both ask that one element be seen first and the rest follow by differences of size. This is a lighter version of the problem, because the reading order (title, then numbers, then charts) is conventional and staff will learn it. Fix: decide which one or two numbers matter most to the person running the library and make them clearly stronger, or set "Overview" back so the numbers lead.

**Smaller things.**
- Type scale: the "Overview" title and the KPI numbers look to be the same size (about 24 px), so the page title and the data compete. The chart titles, the table title and the nav labels are also only a pixel or two apart. Keep about four levels, and let weight and color carry the finer differences (Refactoring UI).
- KPI comparisons: "10,480 in October" is the right comparison, but the reader still has to do the subtraction. Showing the change, and its direction, next to each number would make good or bad visible at a glance. That's a judgment call, not a rule the page breaks. Also, October has 31 days and this period has 30, so the raw totals slightly understate November's pace. If the maker cares about that, a per-day figure or a note would cover it.
- "Most borrowed this month" stops at three rows and gives no way to see more. Add a link to the full list, likely the Loans screen.
- The Holds nav icon looks like a shopping cart or basket, which reads as retail, not as reserving a book. The Settings icon looks more like a sun than a gear. Pick icons that say what the item is.

**What's working.**
- The KPI strip is one card split by thin dividers instead of four separate boxes. Each number sits with its label and a previous-period figure, so the row stays quiet and every number has a reference point. Keep that structure.
- The charts are spare: gray context bars, one accent, a single baseline, days in natural Mon–Sun order, and no gridlines or effects. Most of the ink is data. The fixes above add labels without giving that up.
- The table is set well: numbers right-aligned in tabular figures, light row rules, generous row height, and Title and Author left-aligned on a clear column. It's easy to scan.

**Couldn't judge from a still.** Whether the bars show exact values on hover, and whether the date range ("1 to 30 November 2026") can be changed. If it can, it should look like a control. In this image it reads as plain text.
