**First read.** The eye goes to the purple "Sign in" button first, then up to the red-bordered email field and its message. It reads straight away as a sign-in form for a product called Quillpost, caught just after an email failed validation. It feels calm and familiar, like a standard sign-in page with no surprises.

**What it's for.** My assumption, since I wasn't told: this is the sign-in screen for returning Quillpost users, shown in its email-error state. Its job is to get them signed in, or tell them exactly what to fix, with as little friction as possible.

**Verdict.** It mostly works. The layout is conventional in the right way and the error is in the right place. The biggest problem is the error message: it describes the correct format but doesn't point to what is actually wrong with what the user typed. The second problem is that the sign-up link doesn't look like a link.

**What would move it most**

1. **The error message doesn't help the user find their mistake.** The address `dana.ortiz@exmaple` has two problems: "exmaple" is misspelt and there is no ".com". The message under the field says "Enter an email address in the format name@example.com". The example sits right below the typed address and looks almost the same, so a user scanning the two lines may decide theirs already matches and get stuck. The message only shows the right pattern and leaves the user to spot the difference. Nielsen's heuristic 9 and WCAG 3.3.3 (Error Suggestion) both ask the message to say what went wrong and how to fix it. Name the actual problem in plain words, for example "This address is missing its ending, such as .com". If you can also catch likely domain typos, offer "Did you mean example.com?". *Defect*: this is the one moment on the screen where a user can get stuck.

2. **"Create an account" doesn't look clickable.** In the footer line "New here? Create an account", the link is the same grey, weight and size as "New here?", with no underline. The only way to find the link is to move the pointer over it. New users looking for a way in may miss it or doubt it's there. Compare "Forgot your password?", which is clearly a link because it's purple. Norman's signifiers and Nielsen's heuristic 4 (consistency) both apply here. Give "Create an account" the same purple link treatment as "Forgot your password?", and keep "New here?" grey. *Defect*.

**Smaller things**
- **Error has no icon.** The error state uses colour (red border and red text) plus text, which passes WCAG 1.4.1. A small warning icon before the message would make the error easier to spot for colour-blind users and anyone scanning quickly.
- **Wordmark and heading are close in size.** "Quillpost" (about 20 px) and "Sign in" (about 24 px) are only a few pixels apart. Colour separates them, so the cost is small, but shrinking the wordmark a step, or swapping it for a logo mark, would make "Sign in" clearly the heading. *Taste*.
- **Two different link colours.** Links use purple and the sign-up link uses grey. Once item 2 is fixed, every link on the page should share one link style.

**What's working**
- **One clear primary action.** The full-width purple "Sign in" button is the only filled element on the screen, so the next step is never in doubt. Keep it as the only strong action.
- **Correct form structure.** Labels sit above their fields and stay visible, the error appears directly under the field that caused it, and the user's input is kept. The spacing makes it clear the error belongs to Email and not to Password, because the gap from the error down to "Password" is clearly bigger than the gap from a label to its field.
- **Plain on purpose.** This is a standard pattern, and repeat users want to get through it without thinking about it. The plainness costs nothing here.

**Couldn't judge from a still**
- When the error fires (when the user leaves the field, on every keystroke, or only on submit), and whether screen readers announce it and link it to the field.
- What the focus state looks like on the fields and the button.
