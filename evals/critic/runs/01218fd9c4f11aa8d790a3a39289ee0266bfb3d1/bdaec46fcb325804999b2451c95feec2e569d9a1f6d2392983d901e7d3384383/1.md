**First read.** Both versions land on the logo, drop to "Recent work", then go to the images. In version 1 the large tan block on the left takes the eye first and holds it. The two narrow images then read as "more", so the eye has a path: lead project, then the others. In version 2 the three equal squares hold the eye equally, so it moves left to right like a catalogue and none of them stands out. Both feel calm, restrained and architectural, which suits a practice site.

**What it's for.** My assumption: this is the home or work page of a small architecture practice. Prospective clients should leave with a sense of the studio's best and most recent building, and then click into a project.

**Verdict.** Version 1 does the job better. Only two things changed: the grid went from one large image plus two narrow ones to three equal ones, and the "Recent work" heading shrank from display size to near-body size. The grid change matters more. Version 1 picks a lead project, the 2025 library, and makes it unmissable. Version 2 gives the newest and largest building the same weight as a canopy from 2023. That reads as an archive, not a point of view. Version 2's smaller heading is the better choice, but it doesn't make up for the lost focal point.

**What would move it most** (for version 1)
1. **The "Recent work" heading is the second-largest thing on the page and says nothing.** At about 50 px it competes with the lead image for first glance. It is also a label any portfolio site could use. Being thin helps it stay back, but it still outranks the project titles by a big step for no gain. (Defect: it uses up first-read attention on a label.) Fix: bring it down to about the size of the project titles, as version 2 does. Or replace it with a line only this studio could write, something about what they build and for whom. Then the large size would be doing real work.
2. **The two narrow columns are tight for their captions.** "Two houses on Weir Road" nearly fills its 272 px column. A longer project name will wrap or run into the gutter, and those tall portrait crops will be hard on buildings, which are mostly wide subjects. (Taste, with a practical cost.) Fix: set the split at about 60/40 or 2:1 instead of roughly 50/25/25. Or stack the two secondary projects in one column so they keep a landscape crop.

**Smaller things.**
- The bottom quarter of the screen is empty in both versions. Show the start of the next row or a link to all projects, so visitors can tell there's more and the page doesn't look finished at three projects.
- The metadata lines are inconsistent. The library has a floor area, but the other two don't. Either give every project area or drop it.
- The grey metadata text (about 14 px on the off-white background) looks close to the contrast limit. Check it reaches 4.5:1 (WCAG 1.4.3).
- The navigation is plain text separated by middots, so the links look small to tap. Check each one has at least a 24 px target (WCAG 2.5.8).

**What's working.**
- In version 1 the image sizes rank the projects, so the studio's lead project comes across without any text saying so. Keep that.
- The type is clean: one family, with the size step from project title to metadata shown by size and colour together. This restraint suits an architecture practice.
- The page has generous, consistent margins and gutters, so it sits on a clear grid.

**Couldn't judge from a still.** The images are flat colour placeholders, so I couldn't judge photography, cropping or how real images change the weight between the three. Check how a busy photo in the narrow columns sits beside a calm one in the lead slot. I also couldn't see how the uneven grid behaves at tablet widths.

Better: version 1
