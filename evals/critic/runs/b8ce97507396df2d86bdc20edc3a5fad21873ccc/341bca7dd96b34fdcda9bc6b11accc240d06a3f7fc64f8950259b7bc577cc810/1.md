**First read.** The eye lands on "Book a workshop seat", runs down four identical label-and-box pairs, and drops into empty white space where the form should end. It reads as a plain web form for reserving a workshop place. It looks clean and quiet but unfinished, like half a page that stopped loading.

**What it's for.** My assumption: a web page where a member of the public reserves one or more seats at a workshop and sends the request to the host.

**Verdict.** As shown, it can't do its job. There is no button, so nobody can actually book. Behind that, every field is a blank free-text box, so the bookings that do come in will be inconsistent and hard for the host to match.

**What would move it most**
1. **There is no way to submit the form.** The column ends at the "Notes for the host" field (around y 514), and below it are about 280 px of empty page with no button, summary or next step. The fields lead the eye down to the last one and then stop. A visitor who fills everything in is left looking for how to finish, and some will assume the page is broken. The empty band sits inside the frame, so this doesn't look like a cropped capture. Still, check in a live browser that a button isn't failing to render. Fix: end the column with one clear primary button, on the same left edge (x 96) and with the same gap the fields use, so the form's own rhythm carries the eye onto it. Label it with the action, for example "Book my seat" or "Request seats". **Defect.**
2. **The fields accept anything, so bookings will come in wrong.** "Workshop name", "Preferred date" and "Number of seats" are identical one-line boxes:
   - The visitor has to remember and spell the workshop's exact name. A typo gives the host a booking they can't match.
   - Nothing shows a date format or a calendar, so dates will arrive in any format, including dates the workshop doesn't run.
   - Nothing stops "two" or 0 in the seats field.

   Fix: make the workshop a select list, or prefill it from the workshop page the visitor came from. Give the date a picker limited to real session dates, and the seats field a number stepper that defaults to 1 and is capped at the seats left. **Defect** (Nielsen, error prevention and recognition rather than recall; Norman, *The Design of Everyday Things*, on constraints).

**Smaller things.**
- **Notes field:** "Notes for the host" (y ≈ 470–514) is one line high, which signals that only a few words are wanted. Make it a multi-line text area about 3–4 lines tall, the usual convention for free notes.
- **Required or optional:** no field says which it is. Mark "Notes for the host" "(optional)" so people don't hesitate or hit surprise errors.
- **No way back:** there's no "Cancel" or "Back to workshops" link. Add a quiet one, styled below the primary button. This matters most if the form opens as a modal or as a step in a flow.
- **Heading versus labels:** the heading and the labels are the same bold weight and the same near-black, so size is their only difference and every line on the page looks equally heavy. Set the labels in a medium or regular weight so the heading stands apart by weight as well as size.
- **Empty right side:** the whole form sits in a column about 480 px wide on the left, and the right ~700 px are blank, so the page looks like a panel whose other half never loaded. Either use that space for the workshop's details (date, price, seats left), which a visitor deciding to book needs anyway, or put the form in a bounded container so the white space looks intended.
- **Copy:** the title says "a workshop seat" (singular) but the form asks for a "Number of seats". Make the two agree, for example "Book workshop seats".

**What's working.**
- **One crisp left edge:** the heading, labels and fields all start exactly at x 96, so the page reads as one ordered column. Keep that edge for the button and anything else you add.
- **Clear label grouping:** each label sits about 10 px above its own field, with about 37 px before the next label, so there's never any doubt which label goes with which box.
- **A neutral palette with room for one accent:** near-black, a grey-blue for the borders, and white, with no hue anywhere. That leaves a single action colour free for the button you add.

**Couldn't judge from a still.**
- Whether the fields show a visible focus ring. A mid-grey border alone wouldn't be enough.
- How the form shows validation errors and confirms success. This matters a lot while date and seats are free text.
