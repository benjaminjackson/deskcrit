**First read.** My eye lands on "Plan and billing," drops to the teal-outlined Co-op card, then jumps to the teal Save changes button, which is the only strong color on the page. It reads at once as a settings page in an admin tool for a small beekeeping co-op. It feels calm and orderly, and a little generic. Nothing on it is confusing until you try to change your plan.

**What it's for.** My assumption: the co-op's treasurer or admin uses this page to check or change the subscription plan, keep invoice details correct, and get past invoices.

**Verdict.** The layout and type are clean, but the page's most expensive action, changing the plan, is unclear: you can't tell when it happens, whether Save commits it, or what it will cost. The page also lists invoices without giving any visible way to get one.

**What would move it most**
1. **You can't tell when a plan change takes effect, or what it will cost.** This is a defect. The plan radio cards sit in their own section, and a full-width rule separates them from Save changes and Cancel, which sit under Billing details. A user who clicks Packer can't tell three things:
   - Did that click just switch them to a plan that costs $84 a month?
   - Does Save changes also commit the plan, or only the billing fields?
   - Does Cancel undo the plan selection?

   Once they click, nothing marks which plan they're on now. The only clue is the Plan column in the invoice table below. Nothing says when the change starts (now or next cycle) or how the current month is charged. A treasurer will hesitate here, or upgrade by accident.

   Fix direction: mark the current plan in its card. Make the plan change its own explicit action, with a button inside the Plan section that names the plan. Next to that action, say when the change takes effect and how it will be charged. Save and Cancel should then clearly cover the billing fields only. This rests on Norman's natural mapping (a control sits next to what it changes) and Nielsen's heuristic 1, visibility of system status (show the current state), plus heuristic 10 for help placed at the step it concerns.
2. **The Invoices table gives no way to get an invoice.** This is a defect. The PB-0912 numbers are set in plain body text, and there's no download or view control in any row. On a billing page, a treasurer usually comes to fetch a document for the books. Either the invoice numbers are links that don't look like links, or there's no way to get the file at all. Fix direction: make getting each invoice an obvious control in its row, either the number styled as a link or a labeled download action. Sources: Nielsen Norman Group on flat elements causing uncertainty, and common sense.
3. **The plan descriptions can't be compared.** This is a copy defect. Backyard is limited by hives ("Up to 10 hives, one seller"), Co-op by members ("Up to 25 members, shared stock"), and Packer says "Unlimited members and batch labels." Each card names a different limit, so a viewer can't answer the question the cards are there for: what do I gain by moving up? Does Co-op cap hives? Does Backyard have shared stock? Fix direction: describe all three plans on the same terms, with the same limits in the same order, so the differences line up across the cards. Only you know the real limits for each plan; the cards need to state them.

**Smaller things.**
- The Packer card's description wraps to two lines, leaving "labels" alone on the second. Its text also starts a few pixels higher and its price sits a few pixels lower than in the other two cards, so the three prices don't line up. This near-miss looks like a mistake (Arnheim; Gerstner, one program for repeated elements). Shorten the line or give all three cards the same text slots so the prices share one baseline.
- "Add the co-op tax number to every invoice" refers to a number that isn't shown on this page, so the user has to remember it or go check Co-op details. Show the number in the checkbox label, or link to where it's set (Nielsen 6, recognition rather than recall).
- No field is marked required or optional. Billing email and Invoice address are presumably required. Mark them, or mark the optional ones (Budiu, Nielsen Norman Group, "Marking Required Fields in Forms").

**What's working.**
- There is one primary action in one color. Teal appears only on Save changes, the selected card's border, and the checked controls, so the page's accent means "chosen or commit." Keep that discipline when you add a plan-change action: give it the primary style and step Save down, or keep exactly one primary button per section.
- Where you are is clear at every level. Settings is bold in the top nav, Plan and billing has a tinted background in the sidebar, and the page title repeats it.
- The invoice table is set correctly: amounts are right-aligned with figures that line up, the rules are light, and "Paid" stays in plain text instead of a colored badge.

**Couldn't judge from a still.** Focus indicators on the plan cards and fields. Whether clicking a plan card applies the change immediately, which settles finding 1: check this in the live app.
