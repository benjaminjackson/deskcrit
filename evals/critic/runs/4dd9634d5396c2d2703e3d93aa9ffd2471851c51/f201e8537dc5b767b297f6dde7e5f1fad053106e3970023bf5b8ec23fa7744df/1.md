**First read.** The eye goes to "Edit post", then splits between two identical black buttons, "View site" at the top right and "Publish" at the bottom right. It looks like a clean but generic editor for a small community newsletter. It feels calm and tidy. Then you notice the post has no title, and there is nowhere to give it one.

**What it's for.** Nobody told me, so I'm assuming this: a parish volunteer, probably not technical, writes a newsletter post and publishes it with confidence.

**Verdict.** The page is tidy, but it isn't ready for real use. The volunteer can't title the post. They can't tell whether the post is a draft, published or saved. And the most important button, Publish, has to compete with a link styled exactly like it. Fix the missing title and the missing status first.

**What would move it most**
1. **There is no title field. (Defect.)** The only heading is "Edit post", which names the screen, not the post. The body field has no label either. Readers of a newsletter scan a list of titles, so either this post goes out with no title, or the system makes one up. The volunteer has no say in either case and can't check it before pressing Publish. Add a labelled Title field above the body, at a size close to how the title will appear on the site, and label the body field too (WCAG 2.4.6; NN/g on visible field labels).
2. **Nothing shows the state of the post. (Defect.)** This screen doesn't say whether the post is a new draft, an already published post being edited, or saved at all. "Save draft" and "Publish" sit side by side with no context. So a volunteer editing a live post can't tell whether Publish will change what parishioners already see, or whether closing the tab will lose their work. Show the status near the title, for example "Draft · saved 2 minutes ago" or "Published 3 May · you have unsaved changes". If the post is already live, change the button label to "Update" (Nielsen heuristic 1, visibility of system status).
3. **Two primary buttons. (Convention, and here it costs something.)** "View site" in the header has the same filled black style as "Publish". From a distance the page has two equal calls to action, and the eye checks both before it settles. "View site" is navigation, not the task on this page. Make it a text link or an outline button, so the filled black style means "this commits your work" and appears only once (Material Design, "Buttons", emphasis levels).
4. **The toolbar speaks code and gives no visual hints. (Defect for this audience.)** "B I U S" are all set in the same bold upright letters, so I doesn't look italic and U isn't underlined. The buttons don't show what they do (Norman, signifiers). "H1 H2" and "</>" are developer terms that a parish volunteer won't recognise (Nielsen heuristic 2). The glyphs also look about 16 px wide with tight gaps, which is likely under the 24 px minimum (WCAG 2.5.8; measure in the browser). Draw each letter in its own style, use "Heading" and "Subheading" or a style menu, and drop the code button. A link button is the one tool this audience would actually need.

**Smaller things.**
- Body text in the editor runs to about 100+ characters per line because the editor spans the full 860 px column (Bringhurst: 45–75). Narrow the editor's text area, or let it match the width the live site uses so the preview is honest.

**What's working.**
- The single centred column and generous white space keep the task in front of you. Nothing competes with the writing. Keep this restraint while you add title and status.
- The pairing of "Save draft" (outline) and "Publish" (filled) at the bottom right is the right hierarchy and the right place. It only needs to be the sole filled button on the page.
- The body text is a plain, readable size with comfortable line spacing. The editor reads like the finished post, not like a form.

**Couldn't judge from a still.**
- Focus indicators on the toolbar and buttons, and whether the toolbar shows the active state (for example, B highlighted while the cursor is in bold text).
- Whether keyboard shortcuts (Ctrl/Cmd+B etc.) work, or have tooltips.
