I've finished the checklist and looked up the reference entries for the lines that failed. Here is the critique.

**First read.** The eye goes to the bold title, then drops straight into a heavy black grid of 28 boxes all the same weight. I read it at once as a ferry timetable for someone on the north bank, and it feels clean and official but also stiff, like a form you fill in. The black cage gets noticed before the times inside it do. Nothing tells me which rows are the exceptions, so "does it run today?" means reading the right-hand column row by row.

**What it's for.** My assumption, since I wasn't told: a passenger timetable on a web page or sign, showing someone at North landing when the next ferry leaves today and when it gets to the market quay.

**Verdict.** It works. The table is readable, it's in time order and nothing in it misleads. But the heavy cell borders and the repeated "Period" labels give the structure more weight than the times, and the one thing that changes from row to row, which days a sailing runs, looks the same as everything else. It's a correct table that makes the passenger do the sorting.

**What would move it most**
1. **The grid is louder than the times.** Every cell has a near-black border about 2 px thick, as dark as the numbers. The eye reads compartments, not a timeline, and scanning down the "Leaves north" column means crossing a thick rule every 57 px. Lupton says the rules in a data table "should illuminate the relationships among data, not trap each entry inside a heavily guarded cell" (*Thinking with Type*, p. 157). Tufte calls this non-data ink. **Convention, and here it costs scanning speed.** Fix: remove the vertical rules and the outer frame. Keep at most thin, pale horizontal dividers or a pale tone on alternate rows, so the times are the darkest thing in the table.
2. **The "Period" column repeats itself and doesn't group anything.** "Morning", "Midday" and "Afternoon" each appear twice, each pair in separate boxes with the same gaps as everything else. The word adds nothing the time doesn't already say, and the boxes split each pair instead of joining it. The column also takes the leftmost and most-read spot that the departure time should have. **Defect (it takes the first glance and returns nothing).** Fix: either drop the column and lead with "Leaves north", or turn the periods into group labels. Write each label once, above or beside its rows, with a larger gap between groups than within them (Arnheim on grouping by proximity).
3. **The exceptions are hidden.** Two sailings run only on weekdays (12:40 and 17:10) and one only at weekends (19:30). They are set in the same weight and colour as "Daily" in the last column. On a Saturday, someone has to read all seven rows to learn that 12:40 and 17:10 won't come. Missing a ferry is the costly mistake this piece exists to prevent. **Defect.** Fix: make "Daily" the quiet default (or leave it blank and add a note: "Runs daily unless marked"). Then mark the exceptions with a second cue, such as bolder text or a short tag, so they stand out at a glance.
4. **The copy leaves gaps a stranger has to fill.** "Spring season" gives no dates, so a visitor in late May can't tell whether this table still applies. Passengers hold the operator to dates, so this is a defect, not a style note. The title promises a "River ferry timetable" but shows one direction only. Someone at the market quay will look for the return sailings and find nothing to say where they are. "Leaves north" / "Arrives quay" are cut-down forms of "North landing" and "market quay". They're readable, but they're one more translation for the reader. **Defect (dates, direction); taste (headers).** Fix: put the season's start and end dates in the subtitle. Name the direction in the title, or add the return table, or link to it. Use the full stop names in the column headers.

**Smaller things.**
- The times look set in proportional figures: "11:00" and "17:10" come out narrower than "06:40", so the right edges don't line up. Switch on tabular figures (Bringhurst 4.4.3) so the columns align. This is hard to confirm from a screenshot; check the font's `tnum` setting.
- Every crossing takes 12 minutes, so the arrival column repeats one fact seven times. Keep it if passengers need to plan a connection; otherwise one line ("Crossing takes 12 minutes") would let the departure time lead on its own.

**What's working.**
- A tight type scale: title, subtitle and table text, three sizes with clear steps, and bold column headers set apart by weight rather than another size. Keep it.
- The rows are in departure order with even spacing, so once the rules are lighter the left column will read as a clean timeline.
- The page has a generous left margin, and the title, subtitle and table share one left edge. It looks calm and official, which is right for a timetable.

**Couldn't judge from a still.** How the four-column table reflows on a phone at 320 px width. This matters if passengers will check it at the landing.
