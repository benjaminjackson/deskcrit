**First read.** The eye lands on the dialog title "Archive this project?", reads the two-line explanation, and ends on the blue "Archive project" button at bottom right. This is a confirmation dialog in a project-management tool, for someone who has just asked to archive "Harbour Road refit". It feels calm and clear, with no alarm. That fits, because archiving can be undone. The only change between the versions is the Cancel button: outlined in version 1, solid blue in version 2.

**What it's for.** My assumption: the dialog confirms a reversible archive, tells the user what will happen, and makes both choices clear without inviting a misclick.

**Verdict.** Version 1 does the job and version 2 breaks it. In version 2, Cancel is the same filled blue as "Archive project", so the dialog loses its one clear action. The two choices look alike, and only the labels tell them apart.

**What would move it most**
1. **Version 2 makes Cancel look like the main action.** In the bottom-right button row, "Cancel" and "Archive project" are the same filled blue with the same bold white label. They differ only in width. The user sees two equal buttons and has to read both labels to tell the confirm button from the way out. Someone who clicks by position or habit can hit the wrong one. Seen in greyscale or squinted at, the pair merges into one block. Spending the accent colour on Cancel also weakens what blue means across the product: blue no longer marks the action. This is a convention break with a real cost (Material Design 3, "Buttons": "Use visually-prominent filled buttons for the most important actions"; Nielsen's consistency and error-prevention heuristics). The fix is version 1: give the view one high-emphasis action and style the other actions as outlined or text buttons (Material Design 3, "Buttons"). **Defect.**

**What's working** (applies to both; keep it)
- **The copy.** "The project and its 38 tasks move to the archive. Members can still read them, but no one can add tasks or comments until you restore it." It gives the scope (38 tasks), what still works, what stops, and that it can be undone, all in plain words. It ends on the user ("until you restore it"), so the user can decide without worrying.
- **The confirm button names the outcome.** "Archive project", not "OK" or "Confirm". Read on its own, the button still says what it does.
- **Version 1's button pair.** Filled blue for the action and an outlined white button for Cancel. Both have a clear button shape, the action stands out, and blue rather than red fits an archive that can be undone.

**Couldn't judge from a still.** Which button has keyboard focus when the dialog opens. With the buttons as alike as version 2 makes them, focus on Cancel is the safe default.
