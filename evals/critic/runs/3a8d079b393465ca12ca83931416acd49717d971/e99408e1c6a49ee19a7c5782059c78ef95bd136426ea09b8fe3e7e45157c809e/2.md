**First read.** The bold title "River ferry timetable" catches the eye first, then the heavy black grid takes over. Seven rows of identical boxes, all with the same near-black border, so the eye reads the bars before the times. It reads as a plain, honest utility page for ferry passengers. It feels tidy but rigid, more like a form than a timetable.

**What it's for.** My assumption: it helps a passenger on the north landing find the next ferry they can catch today, and when it gets to the market quay.

**Verdict.** Usable, but heavier and slower to read than a seven-row timetable should be. The full black cell grid, together with columns stretched across the page, breaks each sailing into four separate boxes. The one thing a passenger needs to check first, whether the ferry runs today, is pushed to the far right edge.

**What would move it most**
1. **The grid is stronger than the times.** Every cell has the same dark border, about 2 px, all round: 28 boxes for seven sailings. Those rules are the darkest, most repeated marks on the page, so they compete with the numbers. Each row also reads as four compartments rather than one journey, so a passenger's eye has to jump fences to get from "17:10" to "Weekdays". Lupton puts it directly: the rules in a data table "should illuminate the relationships among data, not trap each entry inside a heavily guarded cell" (*Thinking with Type*, p. 157). Tufte's data-ink argument says the same thing. *Defect (convention-backed).* Fix: remove the vertical rules and the outer frame. Keep thin, pale horizontal rules or a light zebra tint between rows, so the times become the darkest thing on the page and each row reads as one sailing.
2. **The columns are stretched to fill the page, so related facts sit far apart.** The table runs about 1080 px wide, and departure and arrival are about 300 px apart with empty space between them. The day pattern is another 300 px further right. Each column should be about as wide as its content. Because width is set by the page, the eye has to track across a lot of empty space to connect "15:20 → 15:32 → Daily" (Arnheim/Wertheimer on proximity: things that belong together should sit closer than things that don't). *Defect.* Fix: size the columns to their content and keep the table compact, so one sailing reads in a single glance. Give that space to the margin instead.
3. **"Which ferries run today?" takes a full scan.** A weekend passenger has to read the Runs column on every row to rule out the 12:40 and 17:10, and only then finds that the 19:30 is weekend-only. Day of week is the first filter a passenger applies, yet it is the last column and has the same weight as everything else. The Period column, meanwhile, spends a whole column saying "Morning" twice, "Midday" twice and "Afternoon" twice, which the times already tell you. *Taste, argued from the job.* Fix: either drop Period and move Runs next to the departure time, or make the exceptions stand out so they can't be missed. "Daily" is the default, so set it quietly. "Weekdays only" and "Weekends only" are the cases that cause someone to miss a boat.
4. **"Spring season" is a date range with no dates.** A passenger will act on this table and hold the operator to it. "Spring season" could mean March to May, Easter to June, or whatever the operator decided. Someone travelling in early June can't tell whether this table still applies. *Defect (common sense: no catalog entry).* Fix: give the actual dates, e.g. "Valid 1 March – 31 May".

**Smaller things.**
- The times use proportional figures. "11:00" and "11:12" are visibly narrower than "06:40" and "19:30", so the colons don't line up down the column. Switch on tabular figures (Inter has them: `font-variant-numeric: tabular-nums`) so the times line up on the colon (Bringhurst 4.4.3).
- The page covers one direction only. If there is a return sailing from the market quay, it's missing, or the title should say this is outbound only.

**What's working.**
- The type is plain, sized correctly, and has a clean three-level scale: a bold title, a quieter grey subtitle, and bold column headings over regular cells. Keep it.
- The subtitle names the route ("North landing to market quay"), so the passenger knows which direction this is before reading a single time. Keep that line and add the dates to it.
- The 24-hour times and the leaves/arrives pairing are clear and correctly sorted. The data is correct; only the frame around it gets in the way.
