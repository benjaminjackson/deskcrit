**First read.** In version 1 the eye lands on the big "Recent work", drops straight to the wide Coldharbour Lane library tile, then moves right across the two smaller projects. It reads as a calm, confident portfolio page for an architecture practice. In version 2 the eye lands on the bold logo, then slides across three identical tiles without stopping on any of them. Same practice, but it feels like a file browser rather than a showcase.

**What it's for.** My assumption: the home or Projects page of a small architecture practice, showing prospective clients their best recent buildings and inviting them to click through.

**Verdict.** Version 1 does the job better. It decides what matters most, which is the newest and largest project plus a clear page title, while version 2 flattens everything into three equal tiles and a heading the same size as the captions. Both have the same problem: the tiles are flat colour blocks. An architecture portfolio with no pictures of buildings fails its job, whatever the layout.

**What changed, and why it matters**
- **Focal point (defect in v2).** V1 makes the library tile twice the width of the others. That gives the page a lead project and a reading order: biggest first, then the rest. V2 makes all three tiles equal, so no project is presented as more important. The viewer gets a list to browse rather than work to look at, and for a portfolio that means a weaker first impression of the practice's best work (Refactoring UI; Müller-Brockmann on scale contrast giving a page tension).
- **Type hierarchy (defect in v2).** In V2, "Recent work" is about 22 px, the same size as "Coldharbour Lane library" and the other titles. It reads as a stray caption, not as the heading of the page. In V1 it's a clear display size, and the scale has about four distinct levels: heading, project title, nav/logo, meta line. Each level has an obvious job.

**What would move version 1 most**
1. **The images are empty (defect, assuming this isn't a load failure).** All three tiles are flat beige, grey and taupe. For an architecture practice the photographs are the product. Without them the viewer can't judge the work, and the big library tile ends up dominating with nothing in it. If these are placeholders, the layout can't really be judged until real photography is in. If they're meant to load, check that in a live browser. The direction: strong building photography, cropped to suit each tile, with the library shot carrying the most visual weight.

**Smaller things**
- Wide library tile (V1): it spans about 544 px against 272 px tiles with 24 px gutters. That is two "columns" of 272 with the gutter ignored, so the row doesn't sit on a true column grid. Make it span exactly two columns plus the gutter, or set the columns from a real 4-column grid.
- Nav (both): "Projects" isn't marked as the current page, if this is the Projects page. Give the current item a weight or underline change.

**What's working**
- V1's 2:1:1 split: one clear lead project, and the asymmetry feels considered, not decorative. Keep it.
- The caption pattern in both: name in a larger regular weight, then a grey meta line with type, size and year. It's quiet and consistent, and the baselines line up across columns.
- The restrained palette and type throughout. It suits an architecture practice and leaves room for the photography.

**Couldn't judge from a still**
- Whether the tiles are placeholders or images that failed to load (check live).
- Whether the page continues below the empty band at the bottom (about 200 px). If it ends there, the bottom third is dead space.
