**First read.** The eye goes to "Create your account", then drops down a tall, even stack of seven empty fields, and stops on the solid blue button. Within a second it reads as the signup page for a notes app. It looks calm and competent, but the column is long and every field has the same weight, so it reads as a form to get through rather than an easy start.

**What it's for.** My assumption: this is the signup screen for a new user who wants to start taking notes in Quillnest, and the goal is to get them to press "Create account" with as little effort as possible.

**Verdict.** The visual craft is tidy and conventional, and the screen does its job, but it asks for more than it needs to. Two of the seven fields can wait until after signup, and nothing tells the user which fields are required, what the password rules are, or what a "workspace" is. Each of these adds hesitation in front of the one action the page exists for.

**What would move it most**
1. **The form asks for things that can wait.** "How did you hear about us?" (the dropdown just above the button) and "Workspace name" (fifth field) sit between the user and the button. The referral question helps the marketing team, not the user, and it is placed last, right where the user is about to commit. "Workspace name" asks for a naming decision before the user has seen what a workspace is. Both make the form longer and slower to finish. This is a defect: it slows the intended user at the moment they are deciding. Nielsen 8 says every element should support the main task, and progressive disclosure (Nielsen) says rare or optional choices come later. The fix: take the referral question off this screen (ask it after signup, or drop it), and default the workspace name to something like "Ben's notes" that the user can rename later. That leaves four or five fields.
2. **No field says whether it is required, and the two fields that need explaining get no explanation.** There is no asterisk and no "optional" anywhere. So the user can't tell whether they can skip "How did you hear about us?" or "Workspace name", and they will either fill in everything or find out when submitting. The password field gives no rules, so the length and character rules only show up as an error after the user presses the button. "Workspace name" never says what a workspace is or whether others will see the name. This is a defect. Budiu (Nielsen Norman Group), "Marking Required Fields in Forms": mark each required field with an asterisk and explain it once, or put "optional" after each optional label. Nielsen 10: put short help next to the step it concerns. The fix: mark any field that stays optional, and add a one-line hint under Password (for example "At least 8 characters") and under Workspace name, if that field stays.

**Smaller things.**
- "Sign in" (bottom of the card) is the same gray, size and weight as "Already have an account?", with no underline. A returning user who lands here has no visible way out. Underline it or set it in the brand blue (convention: links need more than position to look clickable).
- The dropdown shows an empty value with no prompt, so it looks broken or unfinished. If it stays, give it a "Select one" prompt (common sense).
- The dropdown uses the browser's native chevron, while every other field is custom-styled, so it looks like it came from a different form. Style it to match (Gerstner, *Designing Programmes*: one program for one kind of element).
- The input borders are a pale gray-blue on white and look below 3:1. Measure one border's colour against #FFFFFF, and darken it if it falls under 3:1 (WCAG 1.4.11).

**What's working.**
- The spacing is clear: each label sits about 8 px above its field and about 22 px from the field before it, so every label reads as belonging to its input. Keep that ratio when you add hints.
- There is exactly one strong colour action: the full-width navy "Create account" button. Nothing competes with it. Keep secondary actions, including the Sign in link once it is fixed, visibly quieter than it.
- First and last name side by side is the right exception to a single-column form: a short, related pair that saves one row without breaking the reading order.

**Where it could go further.**
1. *Taste.* Make the subtitle say why Quillnest and not just what the page is. "Start a free workspace for your notes" could sit on any notes app's signup page, so a hesitant user gets no reason to finish. One concrete line about what they will be able to do in the first minute, said to them, would tip a user who is on the fence.
2. *Taste.* Give the page one thing that is Quillnest's own. Right now it is a white card on a pale blue background with Inter-style type and a navy button, the default look of a thousand SaaS signups. One brand-owned element (a colour beyond the navy, the wordmark at a real size, or a glimpse of the product beside the card on this 1280-wide screen, where the card leaves about 400 px empty on each side) would make the moment feel like arriving somewhere specific.

**Couldn't judge from a still.** Focus states on the fields and the button (they need a visible ring at 3:1). Whether the password rules and field errors appear inline when the user leaves a field or only after submitting. Whether the empty dropdown is how it is designed or a capture artefact (check in a live browser).
